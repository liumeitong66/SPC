# 设备运行监控页面调整设计

## 目标

精简设备运行监控页的信息层级，明确设备运行操作，并补齐可追溯的设备综合运行记录页。页面继续适配独立客户部署和可配置设备组织结构。

## 运行监控页结构

页面按以下顺序展示：

1. 设备运行统计卡片。
2. 连接率与传输正常率趋势、当前异常设备。
3. 查询筛选区。
4. 设备运行状态列表。

删除原“监控范围”整行；删除列表标题旁的“共 4 台设备”。筛选区只保留时间范围、设备名称/SN、连接状态、传输状态、重置和查询。

## 字段与状态文案

- “所属组织”改为“所在位置”，数据仍展示完整末级组织路径。
- “待传数量”改为“待补传数量”。该数值只统计平台根据数据序号缺口、失败任务或已创建补传任务识别出的记录；不支持序号或确认机制的设备显示“—”，不得估算。
- 异常设备的持续时间使用完整语义：连接异常显示“已断开 X 小时/X 天”，传输延迟显示“已延迟 X 分钟”。

## 操作栏规则

- “查看记录”始终直接显示。
- 除查看记录外，如果当前设备只有一个可执行操作，该操作直接显示在操作栏中，不出现“更多”。
- 如果有两个及以上可执行操作，统一收入“更多”竖向下拉菜单。
- 停用设备只有“查看记录”。

## 综合运行记录页

新增设备综合运行记录详情页，从运行监控列表的“查看记录”进入。页面包含：

- 面包屑与返回入口。
- 设备概况：设备名称、设备 SN、所在位置、启用状态、连接状态、传输状态、最后心跳时间和最后接收数据时间。
- 查询筛选：时间范围、记录类型、处理结果，以及固定顺序的“重置”“查询”按钮。
- 综合记录列表：发生时间、记录类型、状态变化、记录详情、处理结果、来源/操作人。

记录类型覆盖连接变化、传输异常、补传任务和人工运行操作。列表使用统一表格与分页规范，内容超宽时只允许表格容器内部滚动。

## 交互与边界

- “查看记录”携带设备标识进入详情页；原型根据参数展示对应设备名称。
- 断开连接继续使用二次确认；重新连接、补传和诊断沿用既有反馈方式。
- 1440 × 900 为主要验收尺寸，并检查当前浏览器尺寸；任何弹层、下拉菜单和表格不得越过所属容器或视口边界。

## 验收标准

- 页面不存在“监控范围”整行和列表标题计数文案。
- 筛选区位于设备运行状态列表正上方。
- 字段、持续时间和操作栏符合上述规则。
- 点击任一“查看记录”可进入完整的综合运行记录页并返回。
- 公共脚本和页面内联脚本通过语法检查，HTML 差异无空白错误。
