# 设备运行与数据传输监控设计

## 目标

在每个客户独立部署一套 SPC 集中管理平台的前提下，建立统一、可配置的设备运行监控能力，同时服务生产/质量人员的异常发现和设备运维人员的处置需求。

本次设计放开现有“数据上传监控”页面并升级为“设备运行监控”，同时调整设备管理列表中的设备状态、连接状态和传输状态。平台不集中接收多个客户的数据；客户差异通过独立部署内的设备能力配置、状态阈值和接入适配器消化。

## 页面职责

### 设备管理

- 负责设备资产配置和组织归属管理。
- 支持新增、编辑、启用/停用、删除和查看本机 SPC。
- 列表展示启用状态、连接状态、传输状态和最后接收数据时间的当前快照。
- 不再提供重新连接、断开连接、补传和诊断等运行操作。

### 设备运行监控

- 负责连接与数据传输状态的集中监控、趋势分析、异常发现和运行处置。
- 提供重新连接、断开连接、补传、诊断和查看运行记录等操作。
- 复用现有 `07-数据上传监控.html`，将页面名称和导航名称统一为“设备运行监控”，不新增第三个监控页面。

### 告警管理

- 负责连接中断、传输延迟、积压和失败等告警规则及事件记录。
- 本次仅建立页面之间的职责边界，不新增或改造告警规则页面。

## 状态模型

### 启用状态

表达管理员是否允许平台管理设备，取值为“启用、停用”。原“设备状态”统一改名为“启用状态”。

- 启用设备参与连接和传输监控。
- 停用设备不参与监控、统计和告警；其连接状态和传输状态显示“未监控”。

### 连接状态

表达平台当前是否能够与设备通信，取值为“已连接、未连接、未知、未监控”。

- 已连接使用统一绿色圆点。
- 未连接使用统一灰色圆点。
- 未知用于当前客户或设备不具备可靠连接检测能力的情况。
- 未监控仅用于停用设备。

### 传输状态

表达设备业务数据是否正常到达平台，取值为“正常、空闲、延迟、中断、未知、未监控”。

- 正常：数据在配置的正常时间窗口内持续到达。
- 空闲：设备已连接且已知当前处于非生产状态。只有部署能够获取设备运行状态或生产计划时才启用。
- 延迟：超过配置的延迟阈值仍无新数据，或存在可识别的数据积压。
- 中断：超过配置的中断阈值仍无新数据，或连接已中断。
- 未知：设备不具备足够的传输判定能力，不能伪造确定状态。
- 未监控：设备处于停用状态。

连接状态和传输状态必须独立展示。设备可以处于“已连接 + 延迟”，不能把连接正常等同于传输正常。

## 设备管理页面调整

- 列表中的“设备状态”列改为“启用状态”。
- 在“连接状态”右侧新增“传输状态”。
- 保留“最后接收数据时间”。
- 停用设备的连接状态和传输状态统一显示“未监控”。
- 操作列默认继续展示“编辑、更多”。
- “更多”菜单移除“重新连接/断开连接”，保留“本机 SPC”和“删除”。
- 此处对连接操作的调整替代 `2026-09-01-configurable-device-organization-tree-design.md` 中“设备操作列”的连接操作规定；其他组织树规则保持不变。
- 新增传输状态后，表格必须限制在右侧列表容器内；必要时仅在表格容器内部横向滚动，不得推动组织树或造成页面级溢出。

## 设备运行监控页面结构

### 导航与页面名称

- 取消主脚本中隐藏数据上传监控入口的逻辑。
- 在所有页面的“数据管理”导航组中统一展示“设备运行监控”。
- 页面标题、导航文案和相关权限文案统一使用“设备运行监控”。

### 查询筛选区

复用单板查询页面的筛选组件规范，按以下顺序展示：

1. 时间范围。
2. 设备名称/SN。
3. 连接状态。
4. 传输状态。
5. 重置。
6. 查询。

不提供“设备组织”筛选。筛选区末尾只能保留“重置、查询”，导出和刷新不得混入筛选区。

### 状态概览区

首版固定展示六项：

1. 启用设备数。
2. 已连接设备数。
3. 未连接设备数。
4. 传输正常设备数。
5. 传输异常设备数。
6. 待补传/失败数据量。

停用设备不计入连接和传输异常。传输异常包含延迟和中断。

### 监控分析区

- 左侧展示连接率和传输正常率趋势，使用统一时间轴。
- 右侧展示当前异常设备，包含设备名称、所属组织、异常类型和持续时间。
- 空闲、未知和未监控不得计入传输正常率，也不得直接计为异常；具体统计口径应在页面提示中说明。

### 设备状态列表

列表展示：

1. 设备名称/SN。
2. 所属组织。
3. 启用状态。
4. 连接状态。
5. 传输状态。
6. 最后心跳时间。
7. 最后接收数据时间。
8. 待传数量。
9. 失败数量。
10. 操作。

基础能力为启用状态、连接状态、传输状态和最后接收数据时间。最后心跳时间、待传数量、失败原因、自动补传和诊断属于扩展能力；当前部署不支持时隐藏对应列或操作，不展示虚假数据。

## 运行操作规则

- 未连接设备显示“重新连接”。点击后进入处理中，操作完成前禁止重复点击。
- 已连接设备显示“断开连接”。点击后使用统一确认弹窗进行二次确认。
- 存在延迟或积压且设备支持补传时显示“补传”。
- 传输中断或失败时显示“诊断”。
- 所有设备均可查看运行记录。
- 停用设备不提供重新连接、断开连接、补传和诊断操作。
- 操作成功后更新当前行状态和概览统计；操作失败时保留原状态并使用统一反馈说明失败原因。
- 连接、断开、补传等操作应记录操作人、操作时间和结果。
- 设备自行恢复后，页面自动恢复状态，不要求人工解除异常。

## 独立部署与客户适配

- 每个客户部署独立的平台实例、数据存储和设备接入服务。
- 产品使用统一状态模型，不为不同客户复制页面或硬编码客户名称。
- 部署级配置包括心跳超时、数据延迟阈值、数据中断阈值、是否区分空闲、是否支持积压和补传，以及可见指标和操作权限。
- 设备能力配置包括是否支持心跳、接收确认、自动补传、积压数量、运行状态和诊断。
- 不支持的能力显示“未知”或隐藏扩展字段，不能根据没有依据的数据推断设备状态。

## 异常与边界处理

- 连接状态无法判定时显示“未知”，不能显示“未连接”。
- 只有已知设备处于非生产状态时才显示“空闲”。
- 停用设备显示“未监控”，不触发运行告警。
- 页面刷新或状态更新失败时保留上一次状态，并提示数据更新时间或刷新失败。
- 无匹配设备时使用统一表格空状态，不改变列结构。
- 下拉菜单、确认弹窗、状态圆点、按钮和分页必须复用平台统一组件。

## 页面尺寸与一致性

- 主要设计与验收尺寸为 1440 × 900 px，同时覆盖当前浏览器窗口尺寸。
- 页面内容必须保持在所属容器内，不允许页面级横向溢出、菜单被裁切、图表拉伸或分页越界。
- 筛选区、下拉框、按钮、表格、弹窗、状态标记和分页与现有统一规范一致。
- 修改公共导航和公共组件时同步检查全部 HTML 页面。

## 不在本次范围内

- 不实现真实设备协议、心跳服务、消息队列、数据补传服务和后台接口。
- 不实现跨客户集中监控或多客户数据汇总。
- 不新增设备详情页或第三个监控页面。
- 不改造告警规则和告警日志页面。
- 不增加 CPU、内存、磁盘、带宽等主机运维指标。

## 验收标准

1. 所有页面的数据管理导航中可见“设备运行监控”，入口可正常打开。
2. 页面标题、导航文案和相关权限文案统一为“设备运行监控”。
3. 设备管理列表使用“启用状态、连接状态、传输状态”，三者职责和演示数据一致。
4. 停用设备显示“未监控”，不作为连接或传输异常。
5. 设备管理更多菜单不再包含重新连接和断开连接。
6. 设备运行监控筛选区不包含设备组织，且字段顺序和按钮符合本设计。
7. 状态概览、趋势、当前异常和设备状态列表符合首版范围。
8. 运行操作根据连接状态、传输状态和设备能力正确显示，断开连接具有二次确认。
9. 不支持的扩展能力被隐藏或显示未知，不展示无依据的确定状态。
10. 1440 × 900 px 和当前标注窗口下无页面级溢出、遮挡、重叠和菜单裁切。
11. 公共组件和全部页面导航完成一致性检查。
12. HTML、CSS 和 JavaScript 语法及本地页面链接检查通过。
